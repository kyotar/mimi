# mimi — ジャケットで推す、ポッドキャスト発見サービス

## コンセプト

「このジャケット、私が先に見つけた」という発見の誇りを設計する。
発見体験 = 推し活体験にする。

Spotifyのポッドキャスト検索・カテゴリーが分かりづらく、良質な番組が
埋もれている。テキスト検索では「何を聴きたいかわからない」ユーザーが
弾かれ、ジャケットというビジュアル資産が活かされていない。

mimiはジャケットで感覚的に出会い、レコードショップのように
番組を発見する体験を提供する。

## 世界観

**レコードショップ × モダンエディトリアル**

- ジャケットが棚に並ぶ感覚。手に取って、眺めて、ジャケ買いする
- タイポグラフィとスペーシングはモダンに
- Cream / Tan / Inkの有機的な色調で、デジタルなのに手触りを感じさせる

## 差別化

| サービス | 特徴 |
|---|---|
| Spotify | 埋もれる。ビジュアル発見がない |
| Pody | テキスト分析・知識重視。感覚的な発見がない |
| rooom | 収益化・メンバーシップ。発見体験がない |
| **mimi** | **ジャケットで感覚的に出会う。発見体験が核心** |

## ターゲットユーザー

- **Primary**: ポッドキャスト未体験〜ライト層。感覚的な入口が必要
- **Secondary**: 推し番組を人に伝えたい発信者層
- **Tertiary**: 自分の番組を発見されたいポッドキャスト配信者

## 技術スタック

| 役割 | 技術 |
|---|---|
| Frontend | Next.js 14（App Router） |
| Styling | Tailwind CSS |
| Podcast Data | Spotify Web API（Client Credentials） |
| Deploy | Vercel |
| DB（V2〜） | Supabase |

## API方針

- MVP: Spotify Client Credentialsのみ。ユーザーログイン不要
- V2以降: Spotifyログイン（OAuth）・Podcast Index・Claude API導入予定
- APIキーは必ずサーバー側（Next.js API Route）で管理。フロントに露出しない

## フェーズ

- **MVP（現在）**: ジャケットギャラリー・番組詳細・Xシェア
- **V2**: Spotifyログイン・推し活アクション・AIレコメンド・ランキング
- **V3+**: コミュニティ・ポッドキャスターダッシュボード

## 開発ルール（CLAUDE.md参照）

- TypeScript厳守。any型は使わない
- APIキーはサーバー側のみで使用
- エラーハンドリングを必ず実装する
- デザインは DESIGN.md に従う
